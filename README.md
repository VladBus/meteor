# meteor

Загрузка оперативных изображений БРЛК «Метеор-М» с FTP и поддержание порядка TIFF-архива по дате съёмки.

## Что делает скрипт

1. Проверяет весь существующий архив и перемещает снимки в недельные каталоги.
2. Удаляет только пустые каталоги, оставшиеся от старой структуры. Файлы не удаляет.
3. Подключается к FTP-серверу, ищет файлы по маске и скачивает отсутствующие снимки.
4. После загрузки проверяет структуру архива, ищет посторонние файлы, временные PART и снимки не в своих каталогах.
5. Пишет журналы в logs\meteor.log и logs\batch_startup.log.
6. Не обрабатывает изображения через GDAL и не отправляет email.

## Структура архива

Используются семидневные интервалы внутри каждого календарного месяца, а не ISO-недели. Это позволяет не разделять одну мозаику между месяцами и сохраняет структуру, простую для ручного просмотра:

    Z:\ENVISAT\METEOP\2026\10\01-07\METM24_20261005t030639_13488_1_1_BRLK_RLI_log10.tif
    Z:\ENVISAT\METEOP\2026\10\08-14\...
    Z:\ENVISAT\METEOP\2026\10\15-21\...
    Z:\ENVISAT\METEOP\2026\10\22-28\...
    Z:\ENVISAT\METEOP\2026\10\29-31\...

Дата определяется из имени METM24_YYYYMMDDtHHMMSS_. Каталоги последней недели месяца автоматически заканчиваются последним числом этого месяца: например, 29-30 в апреле и 29-31 в октябре.

Существующие дневные каталоги, например 2026\10\05, будут пересмотрены при следующем запуске: распознанные снимки переместятся в недельные каталоги. После переноса пустые старые каталоги удаляются.

## Проверка порядка и посторонних файлов

Подготовительная сортировка обходит архив рекурсивно. Аудит в конце запуска проверяет правильность расположения снимков и регистрирует:
- снимки с корректной датой, но не в целевом недельном каталоге;
- TIFF по маске с датой, которую не удалось распознать;
- временные файлы с окончанием .part;
- посторонние файлы, не соответствующие маске целевых снимков.

**Посторонние и временные файлы автоматически не удаляются.** Они отмечаются в журнале, чтобы не потерять данные, которые могут оказаться нужными. Пустые каталоги удаляются автоматически. Если аудит обнаружил замечания, программа завершится с ненулевым кодом возврата — такие файлы следует проверить вручную.

По умолчанию маска METEOR_FILE_GLOB=METM24_*_BRLK_RLI_log10.tif. При этом распознаются оба расширения — .tif и .tiff.

## Установка

В CMD:

    cd /d E:\Programming_Work\VScode_Work\meteor
    .venv\Scripts\activate.bat
    python -m pip install -r requirements.txt

Создайте локальный .env из .env.example и укажите учётные данные FTP. Настоящий .env исключён из Git.

Не храните пароли в main.py, run_meteor.bat, README или других отслеживаемых Git-файлах.

## Запуск и тестирование

Запуск без Планировщика:

    .venv\Scripts\python.exe main.py

Запуск тестов:

    .venv\Scripts\python.exe -m unittest discover -s tests -v

Запуск через BAT:

    run_meteor.bat

run_meteor.bat вызывает .venv\Scripts\python.exe непосредственно и записывает вывод в logs\batch_startup.log. Основной журнал — logs\meteor.log.

Тесты проверяют разбор даты, границы недельных каталогов, работу с .tif/.tiff, сортировку, обработку конфликтов и аудит. Они не подключаются к реальному FTP и не изменяют сетевой архив.

## Настройки .env

- METEOR_FTP_HOST — адрес FTP-сервера.
- METEOR_FTP_PORT — порт FTP, обычно 21.
- METEOR_FTP_USER и METEOR_FTP_PASSWORD — учётные данные.
- METEOR_FTP_REMOTE_DIR — удалённый каталог; точка означает текущий каталог после входа.
- METEOR_FTP_TIMEOUT — сетевой тайм-аут в секундах.
- METEOR_DEST_DIR — корень локального архива.
- METEOR_FILE_GLOB — маска имён целевых снимков.
- METEOR_LOG_DIR — каталог журналов; относительный путь считается от каталога проекта.

## Повторные и неполные загрузки

- Уже существующий файл того же размера пропускается, если FTP-сервер сообщает размер.
- Загрузка выполняется во временный файл .part; целевой файл заменяется только после успешной передачи и проверки размера.
- Если размер удалённого файла получить нельзя, существующий локальный файл не перезаписывается.
- При конфликте локальной сортировки исходный файл и существующий файл назначения сохраняются, а аудит отметит файл, оставшийся не на своём месте.
- Журнал ротируется при достижении 5 MiB; сохраняется до пяти архивных журналов.

## Планировщик заданий Windows

1. Откройте taskschd.msc и создайте задачу с нужным триггером.
2. В действии укажите путь к run_meteor.bat.
3. Убедитесь, что задача выполняется под учётной записью, имеющей доступ к FTP и архиву.
4. Проверьте оба журнала после ручного запуска задачи.

Сопоставленный сетевой диск Z: может быть недоступен фоновой задаче под другой учётной записью. Для надёжной работы предпочтителен UNC-путь сетевого ресурса, если он известен, либо тот же пользователь Windows с проверенным доступом к Z:.

Обычный FTP не шифрует учётные данные. Если владелец сервера поддерживает FTPS/SFTP, стоит уточнить возможность перехода на защищённый протокол.
