# meteor

Загрузка оперативных изображений БРЛК спутников «Метеор-М» с FTP и сортировка TIFF-архива по дате съёмки.

## Что делает скрипт

1. Проверяет архив на сетевом диске и сортирует ранее загруженные файлы по дате из имени.
2. Подключается к FTP-серверу, ищет файлы по заданной маске и скачивает отсутствующие.
3. Сохраняет изображения в структуре YYYY\MM\DD, например:

       Z:\ENVISAT\METEOP\2026\10\05\METM24_20261005t030639_13488_1_1_BRLK_RLI_log10.tif

4. Пишет журнал в logs\meteor.log и журнал запуска .bat — в logs\batch_startup.log.
5. Не обрабатывает изображения через GDAL и не отправляет email.

Скрипт выполняет один цикл и завершается. Для ежедневного запуска предназначен Планировщик заданий Windows.

## Установка

Откройте CMD в каталоге проекта:

    cd /d E:\Programming_Work\VScode_Work\meteor
    .venv\Scripts\activate.bat
    python -m pip install -r requirements.txt

Создайте локальную конфигурацию, скопировав .env.example в .env. Укажите имя пользователя и пароль FTP в .env. Настоящий файл .env исключён из Git.

Не храните пароль в main.py, run_meteor.bat, README или других отслеживаемых Git-файлах. Пароль, переданный открытым текстом в переписке, следует заменить у владельца FTP-сервера.

## Первый запуск

    python main.py

После запуска проверьте logs\meteor.log. Код завершения 0 означает, что критических ошибок не было; ненулевой код сообщает Планировщику заданий об ошибке.

Проверьте unit-тесты:

    python -m unittest discover -s tests -v

Тесты проверяют разбор даты, целевой путь и сортировку локальных файлов. Они не подключаются к реальному FTP и не изменяют сетевой архив.

## Настройки .env

- METEOR_FTP_HOST — адрес FTP-сервера.
- METEOR_FTP_PORT — порт FTP, обычно 21.
- METEOR_FTP_USER и METEOR_FTP_PASSWORD — учётные данные.
- METEOR_FTP_REMOTE_DIR — удалённый каталог; значение точки означает текущий каталог после входа.
- METEOR_FTP_TIMEOUT — сетевой тайм-аут в секундах.
- METEOR_DEST_DIR — корень локального архива.
- METEOR_FILE_GLOB — маска имён файлов.
- METEOR_LOG_DIR — каталог журналов (относительный путь считается от каталога проекта).

Дата берётся из фрагмента имени METM24_YYYYMMDDtHHMMSS_. Файлы, не соответствующие маске, не скачиваются и не перемещаются. Файл, по имени которого невозможно определить корректную дату, остаётся на месте и отмечается в журнале.

## Защита от неполных и повторных загрузок

- Уже существующий файл того же размера пропускается, если FTP-сервер сообщает размер.
- Передача выполняется во временный файл с окончанием .part. Он заменяет целевой файл только после завершения передачи и проверки размера.
- Если размер удалённого файла получить нельзя, существующий локальный файл не перезаписывается.
- При конфликте имён во время локальной сортировки исходный файл не удаляется.
- Журнал ротируется при достижении 5 MiB; сохраняется до пяти архивных журналов.

## Планировщик заданий Windows

1. Откройте taskschd.msc и создайте задачу с ежедневным триггером на 21:00.
2. В действии укажите путь к run_meteor.bat внутри каталога проекта.
3. Убедитесь, что задача запускается под учётной записью, имеющей доступ к FTP и сетевому архиву.
4. Запустите задачу вручную из Планировщика и проверьте оба журнала.

Важно: сопоставленный сетевой диск Z: может быть недоступен в фоновой задаче, запущенной под другим пользователем или без интерактивного входа. Для надёжного фонового запуска предпочтителен UNC-путь сетевого ресурса, если он известен; иначе используйте ту же учётную запись Windows и проверьте доступность Z: при запуске задачи.

На представленном скриншоте FTP используется без шифрования. Пароль при таком подключении передаётся по сети незашифрованным. Уточните у администратора, доступен ли FTPS/SFTP; данный вариант скрипта использует обычный FTP, как в текущем подключении.
