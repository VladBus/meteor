# meteor

Загрузка оперативных изображений БРЛК «Метеор-М» с FTP и поддержание порядка TIFF-архива по дате съёмки.

## Что делает скрипт

1. Рекурсивно проверяет существующий архив и перемещает целевые снимки в каталоги ISO-недель.
2. Удаляет только пустые каталоги, оставшиеся от старой структуры. Файлы не удаляет.
3. Подключается к FTP-серверу, ищет файлы по маске и скачивает отсутствующие снимки.
4. После загрузки проверяет структуру архива и регистрирует посторонние файлы, незавершённые загрузки и снимки не на своём месте.
5. Пишет журналы в `logs\meteor.log` и `logs\batch_startup.log`.
6. Не обрабатывает изображения через GDAL и не отправляет email.

## Структура продакшен-архива

Каждая ISO-неделя находится в одной папке внутри ISO-года. Неделя, которая пересекает границу месяца, не разделяется между двумя месячными каталогами.

```text
Z:\ENVISAT\METEOP\
└── 2026\
    ├── W40_2026-09-28_2026-10-04\
    │   ├── METM24_20260928t..._BRLK_RLI_log10.tif
    │   ├── METM24_20261001t..._BRLK_RLI_log10.tif
    │   └── ...
    ├── W41_2026-10-05_2026-10-11\
    └── W42_2026-10-12_2026-10-18\
```

В имени папки используются ISO-номер недели, понедельник и воскресенье. Год папки — ISO-год недели, который около Нового года может отличаться от календарного года даты съёмки. Например, снимок от 1 января 2027 года относится к `W53_2026-12-28_2027-01-03`.

При следующем ручном запуске сортировка обойдёт архив рекурсивно и перенесёт распознанные файлы из старых дневных/месячных папок в новую структуру. После перемещения удаляются только оставшиеся пустые папки.

## Проверка порядка и посторонних файлов

Подготовительная сортировка обходит архив рекурсивно. Аудит в конце запуска проверяет правильность расположения снимков и регистрирует:

- снимки с корректной датой, но не в целевой папке ISO-недели;
- TIFF по маске с датой, которую не удалось распознать;
- временные файлы с окончанием `.part`;
- посторонние файлы, не соответствующие маске целевых снимков. Служебный кэш Windows `Thumbs.db` игнорируется.

**Посторонние и временные файлы автоматически не удаляются.** Они отмечаются в журнале, чтобы не потерять нужные данные. Пустые каталоги удаляются автоматически. Если аудит обнаружил замечания, программа завершится с ненулевым кодом возврата; такие файлы следует проверить вручную.

По умолчанию используется маска `METEOR_FILE_GLOB=METM24_*_BRLK_RLI_log10.tif`. При этом распознаются оба расширения — `.tif` и `.tiff`.

## Установка

В CMD:

```bat
cd /d E:\Programming_Work\VScode_Work\meteor
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
```

Создайте локальный `.env` из `.env.example` и заполните учётные данные FTP. Настоящий `.env` исключён из Git.

Не храните пароли в `main.py`, `run_meteor.bat`, README или других отслеживаемых Git-файлах.

## Запуск и тестирование

Запуск тестов без подключения к FTP и без изменений сетевого архива:

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Ручной запуск полного цикла:

```bat
.venv\Scripts\python.exe main.py
```

Либо через BAT:

```bat
run_meteor.bat
```

BAT вызывает `.venv\Scripts\python.exe` непосредственно и записывает вывод в `logs\batch_startup.log`. Основной журнал — `logs\meteor.log`.

Тесты проверяют разбор даты, ISO-недели в том числе на границах месяцев и лет, работу с `.tif/.tiff`, сортировку, обработку конфликтов и аудит. Они не подключаются к реальному FTP и не изменяют сетевой архив.

**Перед первым запуском на рабочем архиве** убедитесь, что `Z:\ENVISAT\METEOP` доступен, а важные данные имеют резервную копию. Первый запуск перенесёт распознанные снимки из старой структуры в папки ISO-недель. Содержимое самих файлов не изменяется; существующие файлы не удаляются, но пустые старые каталоги удаляются. Файлы на FTP-сервере скрипт не удаляет.

## Настройки .env

- `METEOR_FTP_HOST` — адрес FTP-сервера.
- `METEOR_FTP_PORT` — порт FTP, обычно 21.
- `METEOR_FTP_USER` и `METEOR_FTP_PASSWORD` — учётные данные.
- `METEOR_FTP_REMOTE_DIR` — удалённый каталог; точка означает текущий каталог после входа.
- `METEOR_FTP_TIMEOUT` — сетевой тайм-аут в секундах.
- `METEOR_DEST_DIR` — корень архива.
- `METEOR_FILE_GLOB` — маска имён целевых снимков.
- `METEOR_LOG_DIR` — каталог журналов; относительный путь считается от каталога проекта.

## Повторные и неполные загрузки

- Уже существующий файл того же размера пропускается, если FTP-сервер сообщает размер.
- Загрузка выполняется во временный файл `.part`; целевой файл публикуется только после успешной передачи и проверки размера.
- Если размер удалённого файла получить нельзя, существующий локальный файл не перезаписывается.
- При конфликте имён во время сортировки исходный и целевой файлы сохраняются, а аудит отметит снимок, оставшийся не на своём месте.
- Журнал ротируется при достижении 5 MiB; сохраняется до пяти архивных журналов.

## Планировщик заданий Windows

К настройке Планировщика переходить после успешного ручного запуска и проверки журнала.

1. Откройте `taskschd.msc` и создайте задачу с нужным триггером.
2. В действии укажите путь к `run_meteor.bat`.
3. Убедитесь, что задача запускается под учётной записью с доступом к FTP и архиву.
4. Проверьте оба журнала после пробного запуска задачи.

Сопоставленный сетевой диск `Z:` может быть недоступен фоновой задаче под другой учётной записью. Для надёжной работы предпочтителен UNC-путь сетевого ресурса, если он известен, либо тот же пользователь Windows с проверенным доступом к `Z:`.

Обычный FTP не шифрует учётные данные. Если владелец сервера поддерживает FTPS/SFTP, стоит уточнить возможность перехода на защищённый протокол.
